## The request (Jake, verbatim essentials)

Full review + refactor of `Tick` (rxi-derived) using SyncedTimerClass's idea (per-timer due time in a
min-heap; each update processes only the due prefix). Keep every feature (delay, recur, after, stop/remove,
adjust, reset, getClocks, SafeStopClock, AfterNotTouched) and the prior rebuild's extras, expand them, fix
hidden issues, "SUPER performant and stable". Instance model: `TickAPI.Tick = NewTick.new();
TickAPI.Tick.update(dt)` per event hook, plus a clean way to register/manage processors on different
RunService hooks. Decide the time model (rolling accumulated dt vs passed value as insertion point).
ForceEventComplete (fires; distinct from stop/remove). Chained ticks / ticks inside ticks. Built-in
protection around removing a timer. Built with MiddleClass/BaseClass.

## Settled (do not re-argue)

| # | Decision | Evidence |
|---|---|---|
| D1 | **Core = indexed binary min-heap** over parallel `due[]` / `item[]` arrays owned by each scheduler; each handle stores its heap position (`_HeapIndex`, 0 = not in heap) and creation `_Seq` (equal-due tie-break, FIFO); hole-move sifts; ownership check `item[h._HeapIndex] == h` on remove/update. True O(log n) remove/re-key. No lazy deletion, no generation-stale entries, no rebuild, **zero allocation in Update**. | algorithms F-ALG-1/2/3/7/14 (2.7–4.5× faster than prior, 0 B idle garbage, no rebuild spikes); prior-build B-09/B-10 |
| D2 | **Time model = per-scheduler virtual clock.** `Update(dt)`: `now += dt * TimeScale`. `UpdateTo(absoluteNow)`: sets now through an offset (exact at scale 1; pause accumulates the gap into the offset); a backwards value is clamped and counted, never an error. Both share one advance+dispatch. The core requires a finite number `dt >= 0` (else error). The RunService driver sanitizes before calling: NaN/negative → 0, clamp to `MaxDt` (default 0.25 s, configurable, may be disabled). | algorithms R5/F-ALG-12; roblox-timing RT-2/RT-6; syncedtimer S-11/RT-7; prior-build B-05; semantics SEM-03 |
| D3 | **Dispatch loop**: `while n > 0 and due[1] <= now do … end`, re-reading state every iteration. A one-shot is popped and marked Fired BEFORE its callback; a recurring handle is re-keyed in place BEFORE its callback; chained children are armed (at the parent's due) BEFORE the parent's callback. **No scheduling code runs after any callback** (only bookkeeping such as restoring the base carry), so a callback's own stop/reset/adjust/pause always wins and a parent that errors still arms its children (documented deviation). | algorithms R2/F-ALG-11; prior-build OPEN-8/B-06/B-13; legacy L-06; semantics non-negotiables |
| D4 | **Base carry**: implicit arms (a timer created inside a callback, a recurring re-arm, a chained child) measure from the firing entry's ideal due (rxi `err` semantics — drift-free); explicit operations (Reset, Adjust, Resume, Complete, SetRemaining) measure from `now`. The legacy quirk where a timer created inside a RECURRING callback is measured from the NEXT due (err positive, L-01/B-03) is a bug and is NOT reproduced (documented deviation, Q-J1 for Jake). | prior-build B-01 (critical infinite loop), F-ALG-13, semantics SEM-06, legacy L-01 |
| D5 | **No synchronous immediate-fire path.** A nested past-due timer fires later in the SAME update through the normal loop; the handle is always returned before it can fire. A per-update **runaway valve** bounds dispatches of entries armed during the current pass (default 1000): on hit, warn once through OnError and leave the rest in the heap for the next update (never hang). Zero-delay timers armed outside a pass fire on the next update. | legacy L-04; prior-build B-02 (critical busy loop); semantics SEM-09; callsites: no literal 0 delay live |
| D6 | **Recurring catch-up policy** per scheduler with per-handle override: `"cap"` (default; `MaxCatchUp` fires per handle per update, remainder dropped by snapping the key to the first grid point > now, phase preserved), `"all"` (legacy burst, still bounded by the valve), `"drop"` (= cap 1). Per-update counting through numeric handle fields (`_Burst`, `_BurstSerial`), never per-update tables. Default MaxCatchUp = 8 (covers the live 0.01 s Tickr refresher ≈ 2 fires/frame and the 1/24, 1/30 flipbooks). | callsites CS-07; legacy L-08; prior-build B-21; algorithms R3; roblox-timing RT-10 |
| D7 | **ForceEventComplete = `Complete()`**: re-keys the entry to `now` so it fires exactly once inside the NEXT Update in due order (deferred; safe against re-entrancy in the five live teardown callers). One-shot → Fired; recurring → fires once then re-arms from now (option `stop = true` ends it); Paused → completes without resuming (stays Paused with the full period afterwards); Chained → detached and armed at now. `CompleteNow()` is the explicit synchronous variant using the same fire path (no-op with `false` when called from inside its own callback). Terminal handles → `false`. Legacy alias `ForceEventComplete`. Never confuse with Stop/Remove (callback never runs). | syncedtimer S-01/S-14; callsites CS-04; algorithms R6; roblox-timing rules; semantics F-rows (default is Q-J2) |
| D8 | **Handle states** Pending / Paused / Chained / Fired / Stopped (numeric internally, names exported). Every state operation is **total**: inapplicable state → no-op returning the handle; terminal → no-op. `After()` on a Fired parent arms the child from now; on a Stopped parent returns a child already Stopped (never returns the parent). Pause while Chained sets a flag honoured when the parent fires. | prior-build OPEN-5/B-07; semantics SEM-04/SEM-07; legacy L-09/L-11 |
| D9 | **Retiming**: `Adjust(newTotal)`: `due' = now + clamp((due − now) / period, 0, 1) × newTotal`, with the whole `newTotal` when the current period is 0; period becomes newTotal; rejects non-finite or ≤ 0. `SetPeriod(p)` affects future arms only. `Reset()` = full period from now (one-shot and recurring). `SetRemaining(x)` = "x more seconds" without touching the period. SyncedTimer's anchored AdjustTime is a bug and is not copied. | syncedtimer S-02/S-12; prior-build OPEN-1; legacy L-10; semantics R-rows |
| D10 | **Validation at the boundary**: delay/period accept numbers and numeric strings (legacy `tonumber` coercion kept) but report the caller's ORIGINAL type on failure; reject NaN, negative, and (for recur) 0; `+inf` is rejected (Q-J3). `fn` must be callable (function or `__call` table). | legacy L-07/L-17; prior-build B-05; semantics I-rows |
| D11 | **Error policy**: every callback runs under `xpcall(fn, debug.traceback)`; per-scheduler `OnError` = `"warn"` (default) \| `"error"` (first message re-raised after the pass completes) \| `function(message, handle)` (its own error is caught and warned). One erroring timer never aborts the frame for the others. | legacy F4/L-03; algorithms F-ALG-10; prior carry-forward |
| D12 | **Re-entrancy is tolerated, never fatal**: `Update` may be re-entered synchronously from a callback or overlapped by a yielding callback (Roblox runs each signal handler as its own thread). The loop holds no state across a callback, so both passes stay correct; the base carry is saved/restored around each callback; `Stats.Reentries` counts it and the scheduler warns once. | legacy L-05/L-16; prior-build B-04; semantics SEM-12; algorithms R2 |
| D13 | **Classes**: `TickScheduler`, `TickEvent` (the handle), `TickAfterNotTouched` are ROOT BaseClass classes (`BaseClass.class("Tick…")`, unique prefixed names; never subclassed; no Stateful/Callbacks/ObjectPool/Beholder; no `__index` declared on them). Handles are built through a **constructor literal with every field pre-declared** (≤ 14 fields) + `setmetatable(t, TickEvent.__instanceDict)` — still real instances (`isInstanceOf` true, `class`/`type` set) at plain-metatable dispatch cost. **No handle pooling** (ABA risk against 68 live SafeStopClock-after-fire sites). The registry module `TickAPI` and the heap are plain tables/ADTs; heap ops are file-local functions over the scheduler's own arrays. | baseclass-conventions F1/F2/F3/F7/F9 + recommendations; algorithms R7; callsites CS-03 (handles must stay tables) |
| D14 | **Platform seam**: one `Env` module resolves BaseClass, RunService and `warn`, branching on `typeof(script) == "Instance"`. Under Lune the tests load `build/vendor/BaseClass.luau` = the live HeroicSouls file with exactly one edit (the load-time `JsonR` require replaced by a no-op registrar), hashed in `reference/SOURCES.md`, never shipped. Every `build/src` module runs unchanged under Lune and Roblox. | baseclass-conventions F6 + strategy (c); vault BaseClass note pattern |
| D15 | **Naming**: canonical members are PascalCase. A frozen **legacy alias set** is declared once per class in a marked LEGACY SURFACE region: scheduler `update/delay/recur/remove/getClocks`; handle `stop/after/adjust/reset` (+ `Destroy`); registry `Tick/Tickh/Tickr/SafeStopClock/GetAfterNotTouched`. Scheduler entry points are **dual dot/colon callable** (per-instance bound closures installed in `initialize`; first arg == self → shift) so all 300+ live dot sites and the two live colon `Tick:remove(h)` sites work. Handle methods are colon-only and start with a cheap misuse guard that raises a descriptive error. | callsites CS-01; baseclass-conventions naming rule; prior-build B-18; semantics S-rows |
| D16 | **Registry / hooks**: the `TickAPI` module boots the built-ins `Tick` (Stepped), `Tickh` (Heartbeat), `Tickr` (RenderStepped, client only; nil on the server as today unless Q-J4 says otherwise) through the same constructor as user schedulers. Hooks: Heartbeat, Stepped, RenderStepped, PreRender, PreAnimation, PreSimulation, PostSimulation, Manual. One RunService connection per scheduler, never per timer; Stepped's `(time, dt)` normalised to dt; client-only hooks refused on the server with a prefixed error; a missing signal on the RunService is a prefixed error, never a raw index error. Every scheduler owns `Bind(hook)/Unbind()/IsBound()` and `Destroy()` (unbind + clear + dead: later arming errors). Manual `Update` on a bound scheduler is allowed and documented. Boot diagnostics: warn once when a Stepped-bound scheduler receives no updates while Heartbeat is alive (Studio Edit-mode trap). Keep `Tickh` on Heartbeat (not deprecated; PostSimulation is a different dt). | roblox-timing RT-1/RT-3/RT-4/RT-11; prior-build OPEN-3/OPEN-7/B-11/B-12; legacy L-18/L-21 |
| D17 | **Tick inside Tick**: a child scheduler is driven by a parent timer (`parent:Drive(child, period)` sugar over `Recur`), and ownership is explicit: `parent:Attach(child)` makes the parent's `Destroy`/`Clear` cascade; `Detach` undoes it. A child's `Update` inside a parent callback is a different instance and is always safe. | semantics N-rows; Jake's ask |
| D18 | **Stop protection**: terminal check first; `Stop`/`Remove` idempotent; `Remove(nil)`/non-handle → returns false, never errors (SafeStopClock semantics; Q-J5 for a strict mode); a handle owned by another scheduler is refused with an error; stopping a parent cascades to still-Chained children; `Clear()` stops Pending, Paused and Chained alike; `SafeStopClock(x)` stays nil-tolerant, idempotent and returns nil. | legacy F3/F8/L-12/L-15; callsites CS-06; semantics S-rows |
| D19 | **Compatibility surface preserved verbatim**: `TickAPI.Tick/.Tickh/.Tickr` with dot-called `.delay(fn, t)`/`.recur(fn, t)` returning table handles, `.update(dt)`, `.remove(h)`, `.getClocks()` (real count now); `TickAPI.SafeStopClock(h)`; `TickAPI.GetAfterNotTouched(t, fn, "Tickh")` with `:Touch()/:Destroy()`; handle `:stop()/:reset()/:adjust(n)/:after(fn, t)`. ## Non-negotiables (any correct design)

Straight from `research/semantics-spec.md` §Non-negotiables plus: zero allocation in an idle Update;
O(log n) arm/stop/re-key; a stop from inside any callback (own or other, due this frame or not) never
double-fires or resurrects; NaN never enters the heap; a throwing/yielding callback never corrupts the
heap or the clock; every public method is total on terminal handles; no code path can hang a frame.
